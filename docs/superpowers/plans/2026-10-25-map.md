# Map (Component 10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The graph pane: the dagre-laid-out map drawn as sticker circles, ripples on the node being taught, pop-out on the open node, the traveling light toward the open node, the hover card, the legend and zoom buttons; and node clicks that open threads, with the prerequisite banner and untaught nodes starting themselves.

**Architecture:** Pure geometry and timing in `lib/graph.ts` (dagre layout, ancestor edges with relay delays, label sizing, banner text), tested with Vitest. `components/Map.tsx` renders React Flow with one custom node and one custom edge type; hover state lives in a small React context so edges can run their light with the Web Animations API. `pages/Goal.tsx` owns node opening: prerequisites check, banner, then `POST …/open` for an empty thread.

**Tech Stack:** `@xyflow/react` 12, `@dagrejs/dagre`, React 19, Vitest, `playwright-core` screenshots against `dev:fake`.

**Spec:** [docs/superpowers/specs/2026-10-25-frontend-design.md](../specs/2026-10-25-frontend-design.md): The map (graph pane): Layout, Nodes, Lines, Hover, Legend, Clicking a node

## Global Constraints

- Node fills: Known `#3FC383`, Frontier `#FFB020`, Missed `#FF5A5F`, Untested `#C5CBD3`, both themes. Outlines, lines, arrowheads and root rings use `--graph-ink` (`#25282E` light, `#9A9DA3` dark).
- Circles r≈52 (goal r≈64), 4px outline (goal 6px), root ring ≈9px outside with a 3px stroke; labels Nunito 700 15px (goal 17px), long labels ≈13px up to 3 lines with "…"; dark labels white with `paint-order: stroke; stroke: rgba(0,0,0,.45); stroke-width: 3px`.
- No dashes, no dimming, no blur, no glow. Re-layout only when the set of nodes or edges changes.
- Reduced motion: still halo instead of ripples, instant pop-out, no light.
- Commits carry no Claude attribution.

## Rulings

- **Ripple and pop-out values** are the spec's: two rings to 1.7× over 2.4s, staggered 1.2s; open node scales 1.2× with `cubic-bezier(.34,1.56,.64,1)` over 0.38s and `drop-shadow(0 12px 14px rgba(37,40,46,.28))` (dark `rgba(0,0,0,.55)`, my call).
- **Light timing (revised 2026-10-25 at the user's request):** the light runs toward the open node, not the hovered one. Line lengths come from the layout (`lineLength`, React Flow's bezier); every line runs at 250px/s with a 20px light, in flow units so it scales with the zoom. An edge starts at `(longest − dist(to) − length) / speed`, where `dist` is the longest distance along the lines to the open node; the cycle is `(longest + light) / speed`. Run with `element.animate` on a white overlay path drawn under the arrowhead. The hover card ends on `onMove`, not `onMoveStart` (which fires on a plain click).
- **Legend** follows `study-v2.html`: a 7px bar with a 1.5px `--graph-ink` border and dividers, key dots 10px with a 2px `--graph-ink` border (the spec's "slim segmented bar" as the user approved it in that mockup).
- **Hover card** sits to the right of the node, or to the left when it would leave the pane (spec's "my call"), rendered in a pane overlay so zoom doesn't shrink it.
- **Evidence dots** show green dots for `correct` then red for the rest; the API gives counts, not order.
- **Clicking a node while a turn runs** switches the view only; it never calls `open` (that would be a 409).
- **Banner composer:** while the prerequisite banner shows, the composer is disabled with its normal placeholder.
- **Label size** switches to 13px when the label is longer than 10 characters (goal: 12), a character-count proxy for "doesn't fit on one line" (my call).

## Rulings made during the build

- **`StudyMap` (Task 2):** the component is `StudyMap` in `components/Map.tsx`; a component named `Map` shadows the global `Map`.
- **Hover card placement (Task 2):** 240px wide, right of the node, else left, else below it when a half-width pane fits neither side.
- **Bounce and arrowheads (Task 2):** the state-change bounce uses `element.animate` on the circle so the fill transition survives; arrowheads are drawn per edge (not SVG markers) so they take `--graph-ink` from CSS.
- **Banner layout (Task 3):** a `.card` in place of the messages, **Go to** (primary) then **Continue anyway** (secondary), left-aligned as in the mockup; the spec gives no order.
- **Banner on every click (Task 3):** a node with weak ancestors shows the banner even when its thread has history; the spec names no exception.
- **Go to (Task 3):** opens `weak[0]` without its own prerequisite check; `weakAncestors` sorts by depth, so `weak[0]`'s ancestors are all known.
- **Prerequisites fetch failure (Task 3):** proceeds as if none are weak; the thread load reports a real outage.
- **Live reply belongs to its thread (Task 3):** streamed text and its error/Retry show only in the thread the turn runs in (followed through `focus`); other threads show only Stop. The walk showed Chain rule's "Thinking" inside Functions, and Retry there would have targeted the wrong thread.
- **Stream without `done` (Task 3):** a turn route that answers 204 (`open` on a thread that gained history meanwhile) is ended client-side with a synthetic `done`, so the composer doesn't stay on Stop.
- **Explicit handles (Task 3):** map nodes carry `handles` at the points React Flow measured from its 5px handles. Controlled nodes rebuilt without `measured` dropped their handle bounds, and every edge vanished after some clicks (4 → 0 after opening the taught node; 4 throughout now).

## Review Focus

1. **A re-proposed graph** (plan feedback) re-lays out and refits; a state change alone never moves a node. Test in Task 1 (`layoutKey`).
2. **Hovering a root** (no ancestors) runs no light and throws nothing. Test in Task 1 (`lightTimings` returns an empty map).
3. **Clicking a node before approval** shows only the hover card; no request is sent. Verified in Task 3's walk.
4. **Clicking a node mid-turn** switches the view, sends no `open`. Verified in Task 3's walk.
5. **Diamond-shaped prerequisites** (two paths of different lengths into a node) still arrive together. Test in Task 1.

- `layout(nodes: { id; kind }[], edges: { from; to }[]): Map<string, { x: number; y: number }>`: dagre `rankdir: 'TB'`, `nodesep: 48`, `ranksep: 64`, each node sized `2 × (radius + 12)`; returns top-left positions.
