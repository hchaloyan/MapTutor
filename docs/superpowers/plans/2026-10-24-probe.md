# Probe (Component 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `quiz` tool. The tutor sends graded multiple-choice items. The browser sees them without answers, the server grades the user's choices and stores them as `quiz_items`, and the tutor gets the results back. Probe strands show up in the study state and on the study.

**Architecture:** `src/server/quiz.ts` holds the `quiz` client tool, which is registered in `TOOLS`. The client-tool interface gains `answered` on `card` and `toolUseId` on `answer`. Node state transitions on quiz-checks are component 6's job; this component only stores check items.

**Tech Stack:** TypeScript, `node:sqlite`, Vitest.

**Spec:** [02-agent.md](../../../02-agent.md) (`quiz` schema, grading), [01-user-flow.md](../../../01-user-flow.md) (Probe), [prompts/teaching-skill.md](../../../prompts/teaching-skill.md) (option construction)

## Global Constraints

- **Grading is on the server.** The correct answers live only in the stored `tool_use` input, and the client sends only option IDs.
- **What the card hides.** Before an answer, a quiz card has no `correctOptionId`, `explanation`, `strand`, or `nodeId`. After an answer, it gains `correctOptionId` and `explanation`.
- **Phases.** The quiz is allowed in `probe`, `plan`, `teach`, and `done`. In probe and plan, every item needs a `strand` and no `nodeId`. In teach and done, every item needs the `nodeId` of a node in this study and no `strand`.
- **Limits.** 1–10 items per call, and 2–6 options per item. Item IDs are unique within a call, and option IDs are unique within an item.
- **Stored items.** A stored `quiz_items.id` is `<toolUseId>:<item id>`, and `quiz_call_id` is the `toolUseId`.
- **The tool description** carries the evenness rule the skill refers to: options are bare claims, parallel in length, grain size, and register, with no asymmetric bolding.

## Review Focus

1. **A quiz card before answering.** No correct answer leaks through either SSE or the thread view. Test in Task 1.
2. **An answer that skips an item or names an option that isn't there.** It's a 400 and nothing is stored. Test in Task 1.
3. **Every problem with a malformed quiz** comes back in one error, so the tutor can fix them all at once. Test in Task 1.
4. **Strand names that differ only in case** count as two strands in the summary, so the tutor sees the exact names it used. Test in Task 1.
5. **A quiz-check naming a node from another study** is rejected. Test in Task 1.

### Task 1: The quiz tool

**Files:**
- Create: `src/server/quiz.ts`
- Modify: `src/server/tools.ts`, `src/server/tutor.ts`, `src/server/studies.ts`, `src/server/context.ts`
- Test: `src/server/quiz.test.ts`

**Interfaces:**
- Consumes: `ClientTool`, `ToolCtx`, `Phase` from component 3
- Changes: `ClientTool.card(input, ctx, answered: boolean)`, `ClientTool.answer(input, answer, ctx, toolUseId: string)`
- Produces:
  - `quizTool: ClientTool`, registered in `TOOLS` after `ask_user_question`
  - The answer shape is `{ choices: Record<itemId, optionId> }`. The `tool_result` content is `JSON.stringify({ results: [{ itemId, chosenOptionId, correct }] })`.
  - `probeStrands(db, studyId): { strand: string; correct: number; total: number }[]`, in order of first use
  - `GET /api/studies/:id` gains `strands: probeStrands(...)`
  - During probe and plan, `studyStateText` adds `Strands used so far (reuse these exact names): a, b` once any probe items exist
- Error copy:
  - Tutor-facing errors are one line per problem, joined with `\n`. Examples: `Quiz item "q1": correctOptionId "z" is not one of its option ids.`, `Quiz item "q2" needs a strand during the probe.`, `Quiz item "q1": node "n9" is not in this study.`
  - User-facing errors: `Answer every question.`, `That isn't one of the options.`
