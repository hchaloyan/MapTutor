# Agent SDK Switch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Claude call goes through the Claude Agent SDK, signed in with the user's Pro/Max subscription, so MapTutor costs nothing per token; the bring-your-own-key flow goes away.

**Architecture:** The tutor keeps its own turn loop, tools, cards and thread model, but each model step becomes a "hop" run by the Agent SDK in one SDK session per thread. App tools are an in-process MCP server; card tools pause the hop with a `PreToolUse` **defer** and resume later without a prompt; `focus_node` ends the hop with a `PostToolUse` `continue: false`. Session transcripts live in SQLite through a `SessionStore`. The `messages` table becomes a display mirror; the model's context is the session. A simulated engine stands in for the SDK in tests and in `dev:fake`.

**Tech Stack:** `@anthropic-ai/claude-agent-sdk` 0.3.310, `zod` 4, Fastify 5, `node:sqlite`, Vitest.

**Spec:** No separate spec. The design is this plan's Rulings, decided in conversation on 2026-10-25. Sources: [Agent SDK TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript), [hooks: defer a tool call](https://code.claude.com/docs/en/hooks), [session storage](https://code.claude.com/docs/en/agent-sdk/session-storage), [custom tools](https://code.claude.com/docs/en/agent-sdk/custom-tools), [legal and compliance](https://code.claude.com/docs/en/legal-and-compliance).

**Sequencing:** Independent of components 10–11, except Task 6, which touches `Chat.tsx`, `TopBar.tsx` and `App.tsx`. The user picks when to run it.

## Global Constraints

- **Personal use only.** Anthropic's terms allow subscription auth for ordinary individual use, not for serving other people. MapTutor runs on the user's machine for the user.
- **Auth:** only `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`). Every SDK call gets an env with `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` deleted, because either one outranks the OAuth token and would bill per token.
- **Isolation:** every `query()` sets `settingSources: []`, `cwd: AGENT_DIR` (`data/agent`, empty), and `CLAUDE_CONFIG_DIR = CLAUDE_HOME` (`data/claude`). Nothing from `~/.claude` (CLAUDE.md, memory, plugins, hooks) reaches the tutor.
- **Models:** tutor `TUTOR_MODEL` (default `claude-opus-5-5`), `effort: 'high'`; side calls `SIDE_MODEL` (default `claude-haiku-5-5`), `effort: 'low'`. `CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000`.
- **Tools:** the only built-in is `WebSearch`. App tools are served as `mcp__tutor__<name>`. The DB, the API and the frontend keep bare names (`quiz`, `ask_user_question`, …).
- **Schema change:** delete `data/maptutor.db` and `data/maptutor-fake.db` after Task 2 (project convention: no migrations).
- **Live calls** happen only in Task 1 (spike) and Task 7 (smoke run). Each needs the user's go-ahead first, because they use plan quota.
- **Frontend visuals:** the user owns every visual detail. Task 6 asks before changing any screen.
- Commits carry no Claude attribution.

## Rulings

- **One SDK session per thread.** `studies.session_id` is the main thread and `nodes.session_id` a node thread. A thread's first prompt carries the project files, the user text and `<study_state>`; later prompts carry the text and `<study_state>` only.
- **`messages` is a mirror.** Rows are written from the SDK stream: the user prompt row when the session reports `init`, assistant rows as they arrive, and tool-result rows unless a row with that `tool_use_id` already exists. `threadView`, summaries and pending cards read it as before.
- **Cards defer.** The `PreToolUse` hook calls the loop's `decide`. A valid card returns `defer`, the hop ends with `stop_reason: "tool_deferred"`, and the assistant row is marked pending. On answer, the route stores the `tool_result` row as today, then resumes the session **with no prompt**. The hook fires again for the same `tool_use_id`, `decide` finds the stored row and answers it, and the handler returns that content.
- **Card side effects run once.** `tool.answer()` runs in the route, before the resume. `decide` never re-runs `onPause` for a call whose card is already pending.
- **Thread switch.** The `focus_node` handler sets a flag, and `PostToolUse` returns `{ continue: false }`. The hop ends after its `tool_result`, and the loop starts the next hop in the target thread with the `[App: …]` note.
- **Retry.** If the thread's last row is a `tool_result` for a client tool, resume with no prompt. Otherwise send the note `[App: Your last reply did not arrive. Reply to the thread as it stands.]`.
- **Dropped with the Messages API:** explicit `cache_control` (Claude Code caches on its own), the thinking-binding and server-side-fallback betas, and `disable_parallel_tool_use`. Parallel calls are handled by the batch rule in Task 5. A refusal still ends the turn with the same message.
- **Usage:** one `usage` row per model per hop, from `result.modelUsage`. An aborted hop records none (`ponytail:` comment).
- **Transcripts:** stored in SQLite (`agent_entries`) by `sqliteSessionStore`, keyed by session id only (`projectKey` ignored), so the 30-day local sweep and a moved repo lose nothing. Deleting a study deletes its transcripts.

Added after the spike (2026-10-25):

- **Tools over HTTP (the user's decision, after S4 failed).** The tutor's MCP server is an endpoint on MapTutor's own Fastify server, `POST /mcp/:hop` on 127.0.0.1. Each hop gets a random id, registered while the hop runs and removed when it ends; an unknown id is a 404. `createSdkMcpServer` isn't used: an in-process tool isn't there when a deferred call resumes. Every query sets `MCP_CONNECTION_NONBLOCKING=false`, so the server is connected before the resumed call runs. `@modelcontextprotocol/sdk` (1.32.2, already installed under the Agent SDK) becomes a direct dependency.
- **The prompt stream stays open until the result.** The hook's answer on a resumed call needs it (S4), and so does `Query.interrupt()` (S7). Stop goes through `interrupt()`, because `abortController` doesn't stop generation.
- **Usage is a per-hop difference.** `result.modelUsage` is cumulative per session (S6). Each hop records it minus the session's totals before the hop, taken from the last stored `cost-state` entry.
- **More query options:** `permissionMode: 'dontAsk'`, `strictMcpConfig: true`, `verbatimPrompts: true` (a student's `@file` or `/command` stays text), `title` (skips the hidden title call). `agentEnv` also drops inherited `CLAUDE*` variables other than the OAuth token.

## Review Focus

1. **`ANTHROPIC_API_KEY` set in the user's shell.** It must never reach the SDK, or the user is billed per token without noticing. Test: Task 4 `agentEnv drops API keys…`.
2. **A card call batched with another tool.** The SDK ignores `defer` when one message holds several tool calls, so the card's handler runs. It must refuse ("call it on its own") rather than skip the card. Test: Task 5 `a card call batched with another tool is refused, not run`.
3. **Answering a card, then the hop fails** (usage limit, network). Retry must resume the deferred call with the stored answer and must not grade or approve twice. Test: Task 5 route test `retry after a failed answer resumes the card call without re-grading`.
4. **Not signed in, or the plan's usage limit reached.** The chat shows plain words naming the fix, not a stack trace. Test: Task 4 `error results read as plain words`.
5. **Deleting a goal.** Its transcripts leave `agent_entries`, and a running turn still blocks deletion (409). Test: Task 5 route test `deleting a goal removes its transcripts`.

- **`simEngine` semantics** (match the Spike findings):
  1. `sessionId` null → new id `sim_<uuid>`. `onSession` always runs first.
  2. A prompt is appended as a user message; it throws if the session has an unresolved deferred call. A null prompt re-asks `decide` for the pending call.
  3. Each model call: `onMessage('assistant', content)`. `pause_turn` continues. Any stop other than `tool_use` ends the hop with that stop.
  4. One `tool_use`: `defer` ends the hop with `deferred`; `deny` adds an `is_error` result with the reason; `run` calls `hop.run`; `answer` uses its outcome.
  5. Several `tool_use`s: `defer` counts as `run`.
  6. Results go into one user message and to `onMessage('user', …)`. An outcome with `stop` ends the hop as `switched`. After `maxTurns` (default `MAX_TURNS`) model calls → `max_turns`. If the model throws while `signal` is aborted → `stopped`.
  7. One `UsageRow` per model call, from `message.usage`.
- **`runTurn` per hop:**
  - the session comes from `studies.session_id` / `nodes.session_id`;
  - the prompt sent is files (new session only) + prompt + `<study_state>`;
  - `onSession` saves the session id and mirrors the prompt row (without file blocks, as today);
  - `decide`:
    - a tool outside the phase is denied with "`<name>` isn't available in the <phase> phase.";
    - server tools run;
    - client tools: a stored `tool_result` row → `answer` with `[resultText, state]`; a card already pending for this id → `defer`; a `check` error → deny with it; otherwise `onPause`, then `defer`;
  - `run`:
    - server tool → `[content, state]`, with `stop` when it switches;
    - client tool → `{ content: ['Call `<name>` on its own, with no other tool call in the same message.'], isError: true }`;
  - endings:
    - `deferred` → mark the row pending, emit `card`, then `done {awaiting: true}`;
    - `switched` → emit `focus`, next hop with the note;
    - `refusal` / `max_tokens` / `max_turns` → existing messages (`max_turns` uses "The tutor took too many steps. Send a message to continue.");
    - `stopped` → save the streamed text if no assistant message arrived after it.
  - Hops cap at `MAX_STEPS` (20).
