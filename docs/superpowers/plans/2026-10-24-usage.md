# Usage (Component 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every model call's token and web-search usage is recorded, and the study and project endpoints show the totals, so friends can see what they're spending on their own keys. Each study has a web-search cap chosen when it's created.

**Architecture:** `src/server/core/usage.ts` holds `recordUsage` and `usageByModel`. `runTurn` records each tutor response. The side-call seams (`htmlToMarkdown`, `summarize`) take an optional `onUsage` callback, so test fakes stay as they are. `studies.search_cap` feeds `max_uses`.

**Tech Stack:** TypeScript, `node:sqlite`, `@anthropic-ai/sdk`, Vitest.

**Spec:** [05-stack.md](../../../05-stack.md) (Caching and cost), [02-agent.md](../../../02-agent.md) (Verification)

## Global Constraints

- **`tools` never changes within a study.** The search cap is `studies.search_cap`, fixed at creation (1–10, default `WEB_SEARCH_MAX_USES` = 3), and it's the only source of `max_uses`.
- **One row per model call**: project, study (NULL for URL imports), the model that served it, input, output, cache read, cache write, and web searches. Null usage fields count as 0. Rows go when their project or study is deleted.
- **Totals are per model**, because tokens from different models cost different amounts: `usage: [{ model, inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, webSearches }]`.
- **A call that fails** records nothing, since there's no usage to read. A side call whose result is then rejected (an oversized page) is still recorded, because it was billed.

## Rulings

- **`search_cap` defaults in the schema** (`DEFAULT ${WEB_SEARCH_MAX_USES}`), so the config constant stays the one source of the default and rows inserted without it still work.
- **Fastify coerces numeric strings** (`"4"` → 4) for `searchCap`, as it does for every schema field. Only non-numbers, non-integers, and values outside 1–10 are rejected.
- **With a server-side fallback**, the row records the model that served the call and the response's top-level usage. Cost if wrong: a rescued turn's declined attempt isn't broken out by model.

## Review Focus

1. **Every model call path records exactly once:** tutor steps (including `pause_turn` continuations), summaries, and URL imports and refreshes.
2. **A search cap outside 1–10 or not an integer** is a 400, and the study's requests always carry its own cap.
3. **Totals** separate models and studies, and URL-import usage shows on the project but on no study.
