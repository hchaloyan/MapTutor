# Plan (Component 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `propose_graph` tool. The tutor proposes an approach and a dependency graph. The server validates it, switches the study to Plan, stores the graph with initial states from the probe evidence, and shows an approval card. Approve moves the study to Teach; feedback goes back to the tutor. The study endpoint and the study state show the graph.

**Architecture:** `src/server/tutor/plan.ts` holds the `propose_graph` client tool and `loadGraph`, which reads a study's nodes with their evidence. `ClientTool` gains an optional `onPause` hook that `runTurn` calls just before it emits the card. Node IDs become per-study.

**Tech Stack:** TypeScript, `node:sqlite`, Vitest.

**Spec:** [02-agent.md](../../../02-agent.md) (`propose_graph`, validation), [03-graph.md](../../../03-graph.md) (initial states), [04-data-model.md](../../../04-data-model.md), [01-user-flow.md](../../../01-user-flow.md) (Plan)

## Global Constraints

- **Node IDs are per-study.** `nodes PRIMARY KEY (study_id, id)`. Edges, `messages.node_id`, and `quiz_items.node_id` reference `nodes(study_id, id)` with composite foreign keys and `ON DELETE CASCADE`. A NULL `node_id` skips the check.
- **Phases.** `propose_graph` is allowed in `probe` and `plan`. The first valid call moves the study to `plan`; approval moves it to `teach`.
- **Replacing the graph** deletes and reinserts the study's nodes and edges in one transaction. That is safe only because node threads can't exist before approval, so posting to a node thread in `probe` or `plan` is a 409.
- **States** come from `initialState` over the study's probe items. `ever_known` is 1 when the initial state is `known`.
- **Evidence** is derived at read time: probe items whose strand is in `node.strands`, plus check items with that `node_id`.
- **Append-only history still holds.** Nothing here changes `system`, the tool list's order within a study, or stored messages.

## Rulings

- **`onPause` runs before the pending message is stored**, not just before the card is emitted. If it throws, no card is left pending over a graph that was never written. Cost if wrong: none found; the turn reports an error either way.
- **The thread lock stays after `answer`.** A pending card means no turn is running on its thread (the turn that made it has ended), so answering can't race a turn and half-apply. Cost if wrong: a duplicate answer in the instant between `done` and the lock's release would get a 409 after its side effects ran.
- **Duplicate edges are ignored** (`INSERT OR IGNORE`) rather than rejected; they change nothing in the graph.
- **State lines say `(2/2 correct)`**, not `(2/2)`, so the tutor can't misread the counts.

## Review Focus

1. **A malformed `propose_graph`** (missing fields, bad kind, unknown strand, cycle) comes back as one error `tool_result` with every problem, and the graph and phase stay unchanged.
2. **A re-proposal** replaces the whole graph, including edges, without leaving rows behind.
3. **The same node ID in two studies** works, and a message can't point at another study's node.
4. **Answering** with anything other than approve or non-empty feedback is a 400 and changes nothing.

### Task 2: propose_graph

**Files:**
- Create: `src/server/tutor/plan.ts`
- Modify: `src/server/tutor/tools.ts` (`onPause`, register the tool), `src/server/tutor/loop.ts` (call `onPause`), `src/server/tutor/context.ts` (graph lines), `src/server/routes/studies.ts` (nodes and edges, node-thread guard)
- Test: `src/server/tutor/plan.test.ts`

**Interfaces:**
- `ClientTool.onPause?(input, ctx): void`
- `proposeGraphTool: ClientTool`, registered after `quiz`
  - `check`: shape problems first (non-empty `approach`; each node has `id`, `label`, `kind` in root/derived/goal, `description`, `strands` as a string list; each edge has `from` and `to`), then `validateGraph(nodes, edges, probe strand names)`. Joined with `\n`.
  - `onPause`: phase `plan`, then replace nodes and edges.
  - `card`: `{ approach }`.
  - `answer`: `{ decision: 'approved' }` sets phase `teach` and `approach`. `{ decision: 'feedback', text }` needs non-empty text. Content is the normalized JSON.
  - Error copy: `Approve the plan or say what to change.`, `Say what you want changed.`
- `loadGraph(db, studyId): { nodes: { id, label, kind, description, strands, state, everKnown, summary, evidence: { correct, total } }[], edges: { from, to }[] }`
- `GET /api/studies/:id` returns `loadGraph`'s nodes and edges.
- `studyStateText` adds, once a graph exists: `Graph:`, one line per node `- id [kind] "label" — state (correct/total); prerequisites: a, b` (or `none`), then `Next node: <id>` (or `none`).
- Posting to a node thread before Teach: 409 `Node threads open once the plan is approved.`
